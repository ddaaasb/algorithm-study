# 6.4. 쉘 정렬 (Shell Sort)

삽입정렬의 보완형 정렬 알고리즘.

정렬이 거의 되지 않을경우 삽입 정렬의 비효율을 개선한 정렬 알고리즘임

## 정렬 흐름

1. gap설정
    1. 전체 배열 길이의 절반 정도로 시작한다. (적당히 정하면 됨)
    2. 매번 gap을 절반씩 줄여나간다. → gap = gap / 2
        - 꼭 절반이 아니어도 됨 (마지막에 gap=1만 되면 됨)
    3. 마지막에는 gap = 1이 되며, 삽입 정렬이 적용된다.
        - 이미 거의 정렬된 상태이므로 삽입 정렬이 빠르게 작동함

2. gap 간격만큼 떨어진 원소들을 삽입 정렬

예를 들어, 배열 [1, 8, 9, 13, 2, 3]이 있을 때,

- gap = 2라면 다음과 같은 인덱스 조합이 생긴다:
    
    > 그룹 1: (0, 2, 4) → 값: 1, 9, 2
    > 
    > 
    > 그룹 2: (1, 3, 5) → 값: 8, 13, 3
    > 

각 그룹을 삽입 정렬해주면:

- 그룹 1 → [1, 2, 9]
- 그룹 2 → [3, 8, 13]

이렇게 gap 간격끼리 정렬된 걸, 원래 배열 인덱스에 반영하면:

→ [1, 3, 2, 8, 9, 13]이 되고, 이 배열을 다음 gap에서 다시 정렬해간다.

1.  gap 간격을 줄이며 전체 배열을 정렬 상태로 만든다
- 점점 가까운 원소들끼리 정렬하면서 전체 배열이 정돈됨
- 마지막에는 gap = 1로 일반 삽입 정렬을 수행한다.
    - 이때는 이미 거의 정렬되어 있어서 삽입 정렬이 매우 효율적으로 작동함

```c
입력 : 크기가 n인 배열 A
출력 : 정렬된 배열 A
for each gap h=[h_0> h_1> ...>h_k=1] //큰 gap부터 차례로
for i = h to n-1 {
	CurrentElement = A[i];
	j=i;
	while(j>=h) and (A[j-h] > CurrentElement){
		A[j]=A[j-h];
		j=j-h;
		}
	A[j]=CurrentElement;
	}
return 배열 A
```

## 시간 복잡도

최악 경웅의 시간 복잡도는 히바드(Hibbard)의 간격 $2^{k-1}$을 사용하면 $O(n^{1.5})$

최선 경우는 좋은 간격을 알아내야 해서 미지수

입력 크기가 매우크지 않으면 좋은 성능→ 임베디드 시스템에서 주로 사용된다.

# 6.6. 정렬문제의 하한

정렬 가능한 모든 경우의 수 n!

→ 이중 하나를 선택하는 문제

비교정렬은 비교결과에 따라 다른 경로로 가는 결정 트리(decision tree)로 표현된다.

트리의 잎노드 개수 ≥ n!

트리의 최소 높이(=비교 횟수 최솟값)≥ log₂(n!)

→ 결정트리는 이진 트리 이고 결정 트리는 정렬을 하는데 불필요한 내부 노드가 없음

 log₂(n!) ≒ log(nlogn)

그렇기 째문에 하한은 log(nlogn)이다.

# 6.8. 외부 정렬(Esternal sort)

입력크기가 매우 커서 읽고 쓰는 시간이 오래 걸리는 보조 기억 장치에 입력을 저장할 수 밖에 없는 상태에서 수행되는 정렬을 일컫는다.
```c
입력: 입력 데이터 저장된 입력 HDD
출력: 정렬된 데이터가 저장된 출력 HDD
입력 HDD에 저장된 입력을 크기가 M만큼씩 주기억 장치에 읽어 들인 후 내부정렬 알고리즘으로
정렬하여 별도의 HDD에 저장한다. 다음 단계에서 별도의 HDD는 입력 HDD로 사용되고,
입력 HDD는 출력 HDD로 사용된다.
while (입력 HDD에 저장된 블록 수 > 1) {
	입력 HDD에 저장된 블록을 2개씩 선택하여, 각각의 블록으로부터 데이터를 부분적으로
	주기억 장치에 읽어 들여서 합병을 수행한다. 이때 합병된 결과는 출력 HDD에 저장한다.
	단, 입력 HDD에 저장된 블록 수가 홀수일 때에는 마지막인 블록은 그래도 출력 HDD에 저장한다.
	입력과 출력 HDD의 역할을 바꾼다.
}
return 출력 HDD
```
